# Windows update recovery — #628

A Windows non-delete-sharing handle on an incoming executable made the native helper fail its second move. It restored the installed executable but discarded an existing rollback slot. Failed rollback also rewrote the backup version before its binary committed, so subsequent recovery labelled signed A as B. These defects were reproduced against source unchanged between 85c0dfe3 and f9f45029 and recorded in [#628](https://github.com/s3ntin3l8/runway-ai-usage-tracker/issues/628).

The helper now preserves the prior backup and its version as `.previous_old` / `.previous_old.version` until replacement and backup-version commit succeed. Failure restores both; existing saved recovery files cause refusal rather than overwrite. The live backup version remains intact until commit, while the new version is staged separately. Rollback helper-start failure retains and restores the staged backup. Uninstall cleans these owned transaction files.

It does not claim a new signed release containing this patch, or a malformed published release through the shipped tray. Recovery's `now` argument explicitly advances the fixture clock past the real 600-second ctime threshold.
